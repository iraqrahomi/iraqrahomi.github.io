1 ما هي Skill في Claude؟

الـ Skill هي مجلد يحتوي على تعليمات تعلّم Claude كيف يتعامل مع مهام محددة أو سير عمل قابلة للتكرار. بدلاً من إعادة شرح تفضيلاتك ومنهجياتك في كل محادثة، تعلّم Claude مرة واحدة واستفد في كل مرة.

📂 بنية مجلد الـ Skill

your-skill-name/
├── SKILL.md              # مطلوب - ملف التعليمات الرئيسي
├── scripts/              # اختياري - كود تنفيذي
│   ├── process_data.py
│   └── validate.sh
├── references/           # اختياري - وثائق
│   ├── api-guide.md
│   └── examples/
└── assets/              # اختياري - قوالب، أيقونات
    └── report-template.md

⚠️ قواعد تسمية حرجة:

  • ✅ اسم الملف يجب أن يكون SKILL.md بالضبط (حساس للحالة)
  • ✅ اسم المجلد kebab-case (مثل: notion-project-setup)
  • ❌ ممنوع: README.md داخل مجلد الـ Skill
  • ❌ ممنوع: وسمات XML < > في الـ frontmatter (قيد أمني)

2 المبادئ الأساسية للتصميم

الكشف التدريجي (Progressive Disclosure)

Skills تستخدم نظام ثلاثي المستويات:

  • المستوى الأول (YAML frontmatter): يُحمَّل دائماً في system prompt. يعطي Claude معلومات كافية لمعرفة متى يُستخدم الـ skill بدون تحميل كل شيء.
  • المستوى الثاني (SKILL.md body): يُحمَّل عندما يظن Claude أن الـ skill ذو صلة بالمهمة الحالية.
  • المستوى الثالث (ملفات مرتبطة): ملفات إضافية يمكن لـ Claude تصفحها عند الحاجة فقط.

التركيب (Composability)

يمكن لـ Claude تحميل عدة Skills في نفس الوقت. الـ Skill الخاص بك يجب أن يعمل جيداً مع Skills أخرى، لا تفترض أنك الوحيد.

قابلية النقل (Portability)

Skills تعمل بنفس الطريقة عبر Claude.ai و Claude Code و API. أنشئ Skill مرة واحدة، يعمل في كل مكان.

3 Skills + MCP: معاً أقوى

💡 تشبيه المطبخ:

MCP يوفر المطبخ الاحترافي: الأدوات، المكونات، المعدات.
Skills توفر الوصفات: تعليمات خطوة بخطوة لإنشاء شيء ذي قيمة.

MCP (الاتصال) Skills (المعرفة)
يربط Claude بخدمتك (Notion, Asana, Linear...) يعلّم Claude كيف يستخدم خدمتك بفعالية
يوفر وصولاً للبيانات في الوقت الفعلي يلتقط سير العمل وأفضل الممارسات
ما يمكن لـ Claude فعله كيف يجب على Claude فعله

4 3 فئات شائعة لـ Skills

📄 الفئة 1: إنشاء المستندات والأصول

الاستخدام: إنشاء محتوى عالي الجودة ومتسق (مستندات، عروض، تطبيقات، تصاميم، كود).

مثال حقيقي: skill frontend-design

"Create distinctive, production-grade frontend interfaces with high design quality. Use when building web components, pages, artifacts, posters, or applications."

تقنيات أساسية: أدلة أسلوب مدمجة، قوالب متسقة، قوائم تحقق للجودة.

⚙️ الفئة 2: أتمتة سير العمل

الاستخدام: عمليات متعددة الخطوات تستفيد من منهجية متسقة، بما في ذلك التنسيق بين عدة خوادم MCP.

مثال حقيقي: skill skill-creator

"Interactive guide for creating new skills. Walks the user through use case definition, frontmatter generation, instruction writing, and validation."

تقنيات أساسية: سير عمل بخطوات مع بوابات تحقق، قوالب، تحسين تكراري.

🔌 الفئة 3: تعزيز MCP

الاستخدام: إرشادات سير عمل لتعزيز الوصول للأدوات الذي يوفره خادم MCP.

مثال حقيقي: skill sentry-code-review من Sentry

"Automatically analyzes and fixes detected bugs in GitHub Pull Requests using Sentry's error monitoring data via their MCP server."

تقنيات أساسية: تنسيق عدة استدعاءات MCP، خبرة ميدانية مدمجة.

5 YAML Frontmatter: الجزء الأهم

الـ YAML frontmatter هو كيف يقرر Claude ما إذا كان سيحمّل الـ Skill. أتقن هذا وستنجح.

الحد الأدنى المطلوب:

---
name: your-skill-name
description: What it does. Use when user asks to [specific phrases].
---

✅ أمثلة جيدة

محدد وقابل للتنفيذ:

description: Analyzes Figma design files and generates developer handoff documentation. Use when user uploads .fig files, asks for "design specs"...

يحتوي عبارات تشغيل:

description: Manages Linear project workflows. Use when user mentions "sprint", "Linear tasks", or asks to "create tickets".

❌ أمثلة سيئة

غامض جداً:

description: Helps with projects.

يفتقد المحفزات:

description: Creates sophisticated multi-page documentation systems.

📋 حقول اختيارية مفيدة:

  • license: MIT, Apache-2.0 (إذا كانت مفتوحة المصدر)
  • compatibility: 1-500 حرف (متطلبات البيئة)
  • metadata: حقول مخصصة (author, version, mcp-server)

6 التوزيع والمشاركة

GitHub Repository

الطريقة الأكثر شيوعاً. أنشئ repo باسم الـ skill واجعله قابلاً للاكتشاف.

البنية: ضع SKILL.md في الجذر، وأضف README.md للتوثيق البشري.

Zip File

اضغط مجلد الـ skill كملف .zip وارفعه مباشرة.

مهم: تأكد من أن الملفات في جذر الـ zip، لا داخل مجلد فرعي.

7 أنماط شائعة وحلول

Skill لا يُحمَّل عند الحاجة

السبب الشائع: الوصف غامض أو لا يحتوي على عبارات تشغيل كافية.

الحل: أضف عبارات محددة يقولها المستخدمون فعلاً. اختبر مع 10-20 استعلام.

Skill يُحمَّل كثيراً (over-triggering)

السبب: الوصف واسع جداً.

الحل: كن محدداً في متى يُستخدم. أضف "Use only when..." بدلاً من "Use when...".

استهلاك رموز (tokens) مرتفع

الحل: انقل التفاصيل إلى مجلد references/ واربطها بدلاً من تضمينها في SKILL.md.

اجعل الوصف أقل من 1024 حرف.

9 رأيي في الدليل

هذا الدليل من Anthropic يستحق القراءة الكاملة حتى لو ما كنت بتستخدم Claude بكثرة. يتميز بأنه:

  • عملي 100% - لا يوجد تنظير، كل صفحة فيها أمثلة قابلة للتنفيذ
  • مبني على خبرة حقيقية - أنماط من skills موجودة في الإنتاج
  • يربط بين النظرية والتطبيق - من بنية المجلد إلى النشر

💡 نصيحة: قبل ما تبدأ ببناء أول skill، استخدم skill-creator المدمج في Claude. يأخذ بيدك خطوة بخطوة ويولد مسودة أولى جاهزة للاختبار.
