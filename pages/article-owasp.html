OWASP Top 10 - أخطر 10 ثغرات ويب

الدليل الأكثر طلباً في أمن تطبيقات الويب. شرح كل ثغرة بأمثلة عملية، استغلال، ودفاع.

؟ ما هي OWASP Top 10؟

OWASP (Open Web Application Security Project) هي مؤسسة غير ربحية تنشر كل 3-4 سنوات قائمة بأخطر 10 فئات من ثغرات تطبيقات الويب. القائمة هي المعيار العالمي الذي يستخدمه:

  • شركات Fortune 500 في تقييم تطبيقاتها
  • الباحثون الأمنيون لاختبار اختراق منظم
  • الحكومات (مثل DoD الأمريكي) كحد أدنى للأمان
  • مطورون كـ checklist لتأمين تطبيقاتهم
A01

Broken Access Control

الوصف: المستخدم يقدر يصل لموارد ما من حقه - مثل تعديل user ID في URL لرؤية حساب غيره.

🎯 أمثلة شائعة:

  • • تغيير ID في URL: /user/123/profile → /user/124/profile
  • • الوصول لـ API endpoints بدون تحقق الصلاحيات
  • • رفع صلاحيات المستخدم من user إلى admin
  • • JWT tokens مزورة أو معاد استخدامها

⚔️ كيف تستغل:

# اختبار IDOR

GET /api/users/1001/profile

GET /api/users/1002/profile <-- مستخدم آخر

GET /api/users/1003/admin <-- محاولة admin

🛡️ الدفاع:

  • • تطبيق authorization في كل endpoint (لا تعتمد على UI)
  • • استخدام policy engines (Casbin, OPA)
  • • تعطيل حسابات المستخدمين المحذوفين فوراً
  • • تسجيل محاولات الوصول غير المصرح بها
A02

Cryptographic Failures

الوصف: ضعف في التشفير أو عدم استخدامه - بيانات حساسة مكشوفة.

🎯 أمثلة:

  • • تخزين كلمات المرور بدون hash (أو MD5 - مكسور)
  • • HTTP بدلاً من HTTPS
  • • استخدام تشفير قديم (DES, RC4, SHA1)
  • • مفاتيح تشفير مكشوفة في الكود

🛡️ الدفاع:

  • • bcrypt أو Argon2 لكلمات المرور (cost 12+)
  • • TLS 1.3 فقط
  • • AES-256 للبيانات في حالة السكون
  • • إدارة مفاتيح في HSM أو Vault
A03

Injection

الوصف: المهاجم يحقن كود ضار في input - SQL, NoSQL, OS commands, LDAP...

🎯 SQL Injection مثال:

# Input عادي

username: admin

password: mypass

# Input ضار

username: admin' OR '1'='1

password: anything

# يصبح الاستعلام:

SELECT * FROM users WHERE username='admin' OR '1'='1' AND password='anything'

🛡️ الدفاع:

  • • Prepared Statements / Parameterized Queries (الأهم)
  • • ORMs (Hibernate, Sequelize)
  • • Input Validation (لكن لا تعتمد عليه وحده)
  • • Least Privilege على DB user

⚡ باقي القائمة المختصرة:

A04

Insecure Design

ثغرات في التصميم نفسه - مو في الكود. مثل workflow يسمح بشيء خطير.

A05

Security Misconfiguration

إعدادات افتراضية، debug mode في production، صلاحيات مفتوحة.

A06

Vulnerable Components

مكتبات قديمة أو معروفة بثغرات - 70%+ من التطبيقات تستخدم مكونات قديمة.

A07

Authentication Failures

ثغرات في login - كلمات مرور ضعيفة، session hijacking، credential stuffing.

A08

Software & Data Integrity

عدم التحقق من updates, CI/CD pipelines مكشوفة, deserialization attacks.

A09

Logging & Monitoring Failures

عدم تسجيل الهجمات - المهاجم يبقى شهور بدون ما حد يلاحظ.

A10

SSRF (Server-Side Request Forgery)

السيرفر يجلب موارد من URL يتحكم فيه المهاجم - يصل لـ internal services.
